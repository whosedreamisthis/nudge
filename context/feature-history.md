# Feature History

- **Project Setup:** Removed the create-next-app boilerplate and demo assets, and initialized shadcn/ui (`base-nova` style, `components.json`, `lib/utils.ts`, Button) with Lucide icons. `app/globals.css` defines the warm yellow→peach→green page gradient, amber primary/ring, rounded cards, and colourful tokens: 7 category colours (`cat-*`), 9 habit colours (`habit-*`), and 6 tinted tile backgrounds (`tint-*`), all exposed as Tailwind colours. Inter is loaded with `next/font` as `--font-sans`. Added an SVG logo (white check on an amber gradient square) as `components/shared/Logo.tsx` and the favicon `app/icon.svg` (replacing `favicon.ico`), plus a sticky top `components/shared/Navbar.tsx` with the logo and "Nudge" on the left, rendered in the root layout. The home page is a placeholder showing the category colours. Configured Vitest (`vitest.config.ts`, `vite-tsconfig-paths`, `npm test` runs `vitest run`) with a smoke test for `cn()` in `lib/utils.test.ts`. Known follow-up: rename the Vitest config to `.mts` and use `resolve.tsconfigPaths` to drop the plugin and the CommonJS warning.
- **Database Schema:** Set up Prisma 7.10.0 with the Neon driver adapter. `prisma/schema.prisma` uses the `prisma-client` generator (output `generated/prisma`, git-ignored) and defines `User` (with `clerkId`, `timezone`, `isDemo`, `demoExpiresAt`), `Category`, `SystemHabit` (with default frequency, target days and optional daily goal), `Habit` (optional `systemHabitId`, `dailyGoal`/`unit`/`stepSize`, `archivedAt`), `HabitTarget` (frequency history with `effectiveFrom`), `HabitCompletion` (`amount`, unique on `habitId` + `date`) and a `Frequency` enum (DAILY/WEEKLY). Deleting a user cascades to their habits and completions; deleting a system habit sets the user's copy to null; categories are restricted. `prisma.config.ts` loads `.env.local` explicitly and uses `DATABASE_URL_UNPOOLED` for migrations; `lib/db.ts` creates one `PrismaClient` with the pooled `DATABASE_URL`. The first migration `20261013204958_init` was applied to the Neon `development` branch only (verified against the branch endpoint; production untouched). Pinned `prisma` to 7.10.0 because npm's `latest` points at an 8.0 release candidate. Docs also record the `app/(auth)/` route group. Known follow-up: run `npx prisma generate` after cloning, since the generated client isn't committed.
- **Clerk Authentication:** Installed `@clerk/nextjs` and wrapped the app in `<ClerkProvider>` (inside `<body>`, with an amber `colorPrimary`) in `app/layout.tsx`. Added `/sign-in` and `/register` using Clerk's `<SignIn />` and `<SignUp />` in the `app/(auth)/` route group with a shared centring layout. `proxy.ts` (Next.js 16's renamed middleware) redirects signed-out users from `/today`, `/habits`, `/progress`, `/journal` and `/focus` to `/sign-in`, and signed-in users from the auth pages to `/today`; these are early redirects only, and each page also checks access itself (`app/today/page.tsx` calls `auth.protect()`), following Clerk's guidance to stop relying on `createRouteMatcher`. `/api/webhooks/*` is left public for the next feature. The home page is now a landing page with "Get started" / "Sign in" that redirects signed-in users to `/today`; the navbar shows Clerk's `UserButton` when signed in. Because `cacheComponents: true` is enabled, the layout content and the user menu are wrapped in `<Suspense>`. Added the Clerk sign-in/up URL and fallback-redirect env vars to `.env.local` and `.env.example`. Also fixed a Vercel build failure by adding `"postinstall": "prisma generate"` (the generated client is git-ignored) and making `prisma.config.ts` tolerate missing database env vars during generate, and changed all buttons to `rounded-md`. Verified on the dev server that signed-out requests to the five app routes return 307 to `/sign-in`. Not covered: an end-to-end sign-up/sign-in test in the browser, and unit tests for the proxy's route-prefix rules (could be moved to `lib/auth-routes.ts`).
- **User Sync:** Added `app/api/webhooks/clerk/route.ts`, which verifies requests with `verifyWebhook()` (400 on a bad signature) and keeps the `User` table in step with Clerk: `user.created` and `user.updated` upsert by `clerkId`, `user.deleted` uses `deleteMany` so habits and completions cascade, and other events are acknowledged with 200. Every branch is idempotent, so Clerk's retries are safe. `lib/session.ts` exports `getSessionUser()`, a React-`cache`d helper that turns the Clerk `userId` into the `User` row, upserting it if the webhook hasn't arrived yet and returning `null` when signed out; later queries scope by its `User.id`. `actions/user.ts` has the `captureTimezone` server action, called from the client component `components/shared/TimezoneSync.tsx` on the Today page, which stores the browser timezone once (only while `User.timezone` is still the `UTC` default, and only if it's a valid IANA zone). `proxy.ts` needed no change because it only redirects the app pages, so the webhook route was already public. Added `CLERK_WEBHOOK_SIGNING_SECRET` to `.env.example`. Vitest tests with a mocked database cover the webhook, the session helper and the timezone action (16 tests passing in total). Also fixed a Base UI console warning on the landing page by adding `nativeButton={false}` to the two link-style buttons in `app/page.tsx`. Verified end to end in dev through a Cloudflare tunnel. Production still needs its own Clerk endpoint and signing secret on the production instance, plus `prisma migrate deploy` against the production database. Known limitation: a user whose real timezone is UTC just keeps the default. Known follow-up: `captureTimezone` runs on every Today page load until a non-UTC timezone is stored.
- **Seed Catalog:** Added `prisma/seed-data.ts` (pure data, so it can be unit tested) with the 7 categories (health, fitness, learning, mindfulness, productivity, sleep, social) and 10 system habits each, 70 in total, using the habit names from the project overview. Each habit has an emoji icon, a description and a default frequency; daily habits use 7 target days and weekly ones 1-6 (for example strength training 3, swim 2, volunteer 1). Ten habits ship with a daily goal, unit and step size: water (2000 ml in 250 ml steps), 10,000 steps (1,000 steps), meditation (10 min), push-ups (20 reps), and minute goals for reading, language practice, instrument practice, study and deep work. `prisma/seed.ts` upserts categories by `name` and system habits by the `categoryId_name` unique key, so it is safe to re-run, and it prints the host it is seeding and the final counts. `prisma.config.ts` registers `seed: "tsx prisma/seed.ts"`, `npm run db:seed` runs `prisma db seed`, and `tsx` was added as a dev dependency. The seed script loads `.env.local` without overriding variables that are already set, so a one-off `DATABASE_URL` in the shell wins. Vitest tests in `prisma/seed-data.test.ts` check the category list, 10 habits each (70 total), unique names, icons and descriptions, daily versus weekly day counts, and that goal, unit and step are set together with a step that divides the goal (23 tests passing in total). Ran against the Neon development branch only (verified the endpoint before seeding), twice, with identical counts, and confirmed 10 habits per category with a query. The production branch has the tables but no catalog yet; seed it once with `DATABASE_URL` set to the production pooled connection string and `npx tsx prisma/seed.ts`. Known follow-up: the seed never deletes catalog rows, so a habit removed from `seed-data.ts` stays in the database until it is deleted by hand.
